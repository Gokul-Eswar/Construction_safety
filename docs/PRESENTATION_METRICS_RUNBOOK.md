# Presentation Metrics Runbook

This runbook produces report-ready metrics directly from the running system.

## 1. What you already have

- Database snapshot file: [docs/metrics_db_snapshot.json](docs/metrics_db_snapshot.json)
- Runtime snapshot file: [docs/metrics_runtime_snapshot.json](docs/metrics_runtime_snapshot.json)

Current status:
- Database snapshot contains valid persisted data.
- Runtime snapshot is empty because no MQTT telemetry was available at capture time.

## 2. One-command capture (recommended)

From project root, run:

powershell -ExecutionPolicy Bypass -File .\tools\capture_presentation_metrics.ps1 -DurationSec 60

This produces:
- [docs/metrics_db_snapshot.json](docs/metrics_db_snapshot.json)
- [docs/metrics_runtime_snapshot.json](docs/metrics_runtime_snapshot.json)

## 3. Required preconditions for live runtime metrics

1. Docker Desktop is running.
2. System is started from [tools/Sentinel.bat](tools/Sentinel.bat) using option 1.
3. Engine is actively processing at least one stream.

If runtime snapshot has telemetry count 0, start system and rerun capture.

## 4. How to read report numbers

Use these fields from snapshot files:

### A. Safety and violation metrics (database)
Source: [docs/metrics_db_snapshot.json](docs/metrics_db_snapshot.json)
- Total violations: violations.summary.total
- First and last violation timestamp: violations.summary.first_ts, violations.summary.last_ts
- Average confidence: violations.summary.avg_conf
- Uploaded and pending sync counts: violations.summary.uploaded_count, violations.summary.pending_count
- Per-zone counts: violations.by_zone
- Per-day counts: violations.by_day_last_30

### B. Real-time system metrics (runtime)
Source: [docs/metrics_runtime_snapshot.json](docs/metrics_runtime_snapshot.json)
- Telemetry throughput: counts.telemetry
- Heartbeat count: counts.heartbeat
- Violations observed on MQTT: counts.violations
- Per-stream FPS stats: stream_fps.<stream_id>.fps
- Latency stats per pipeline key: latency_ms.<key>
- GPU utilization and memory: gpu

## 5. Accurate statements you can use in presentation

If runtime telemetry is present:
- "All performance numbers were captured from live MQTT telemetry during a 60-second run window."
- "Violation analytics were computed from persisted SQLite records generated by the engine."

If runtime telemetry is absent:
- "Persisted safety violation metrics are from production database records; live telemetry capture was unavailable in this run due to broker unavailability."

## 6. Important limitation to mention

Model training metrics such as mAP, precision/recall confusion matrix are not emitted by this deployed runtime service. They must come from YOLO training artifacts (results.csv, confusion matrix images) from the training environment.
